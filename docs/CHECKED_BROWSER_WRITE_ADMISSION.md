# Browser checked write-admission runtime (experimental)

**Status: host-side executable component, not yet an AttoLang guest API.**
The source compiler continues to reject `nb writech`, `nb source << value`, `do writech`, and `do source << value` until a fully checked typed `Future<Result<...>>` guest ABI and compiler lowering exist. In particular, the current JSPI `Future<int>` task handle must **not** be reused as an I/O outcome: it cannot represent EOF, close, cancellation or delivery failure without losing error typing.

`runtime/browser/checked-write-queue.mjs` provides a bounded, single-event-loop-domain **asynchronous host write adapter** that can be integrated behind a future channel import. It is used directly in the Node acceptance tests and inside a real Chromium Worker; it does not pretend to execute an Atto guest `nb writech`.

## Contract

- `new CheckedWriteQueue({slots, maxBytes, maxOwners, sink, supervisor})`; all three quotas are finite and enforced on queued **plus committed** writes. `sink(bytes, ticket_metadata)` is a nonparking async adapter that must acknowledge exactly `bytes.length` or return a structured error. No OS flush or peer delivery guarantee is inferred from admission.
- `submitWrite({owner, generation, payload, mode:'nb'})` returns `{ok:true,ticket,future}` on acceptance; `future` resolves to `{ok:true,written}` or `{ok:false,error:{code,message}}`. The returned Promise is an *internal host future*, **not** the guest `Future<Result>` ABI.
- `submitWrite({owner,generation,payload,mode:'do',onOutcome?/onSuccess?})` requires a supervisor error channel, returns `{ok:true,ticket}` (no caller future), and reports terminal outcomes once. `onOutcome` is typed success/error and `onSuccess` runs only upon successful completion. No success callback can absorb a failure. Suspended/asynchronous callbacks are forbidden and reported.
- Admission rejection returns the **original payload** synchronously with an error; the caller retains ownership. Successful admission makes a bounded independent byte copy to prevent caller mutation; the future compiler lowering must still enforce move/borrow rules.
- A queue is FIFO and processes one committed sink call at a time. `cancel(ticket, {owner, generation})` requires runtime-authenticated owner/generation identity and succeeds only *before* actual sink invocation; a bare or cross-owner ticket cannot cancel someone else's write. a committed sink call cannot be rolled back, and `cancel` reports false. `stopOwner(owner,generation)` fences callbacks and cancels queued work from that generation **and all older generations**; committed work must finish according to its adapter contract. All owner/error events retain their generation identity.
- `close()` fences new submissions and cancels queued work, while committed writes finish; credits and retained byte quota are released exactly once. Cancelled tickets are removed immediately, preventing an unbounded tombstone FIFO under repeated cancel/re-admit. Owner history is capped by `maxOwners`; once its budget is reached, previously unseen owners are rejected rather than dropping generation fences. The ledger is cleared when a terminally closed queue has no outstanding tickets.
- Supervisor exceptions remain observable through `takeSupervisorFailures()` (the Worker controller must inspect these before teardown); they must not be interpreted as completed detached operation delivery. A synchronous or asynchronous supervisor failure **poisons and closes** the queue, with a failure ledger bounded by the pending-slot count. Error text is capped at 256 UTF-16 code units and source-provided error codes must be identifier-shaped. Quota settings and the sink/supervisor functions are immutable after construction. A real host must still surface fatal supervisor failure outside this queue.

## Evidence / limits

`node --test tests/browser-checked-write-queue.test.mjs`: asynchronous host tests for FIFO, capacity and UTF-8 quotas, early rejection preserving payload, copy-on-submit, invalid payloads, write failure, success/error callbacks, owner-scoped cancellation and the pre-invocation race, monotone owner-generation fencing, registry exhaustion, close, reentrant callbacks, malformed sink/thenable results, bounded error text and fatal supervisor escalation.

`tests/browser-async-e2e.mjs` exercises this host runtime inside the actual Chromium Worker via a separate `probe: 'checked_writer'` message. It also retains existing Rust-compiled Wasm guest `await`/task tests and verifies `nb`/`do` guest syntax still fails closed. A green Worker host probe is **not** guest I/O execution, and there is no claim of native, Java, LLVM, .NET, Forge or cross-backend parity.

Remaining: add a nominal typed writable capability, actual `Future<Result<WriteAck, IoError>>` source type and Wasm ABI, import allowlist and typed lowering, move/borrow checks, checked backpressure policy, supervisor CONTROL integration, real guest fixture proving in-order callbacks and cancellation, and cross-backend conformance. Keep the PR draft until those milestones exist.
